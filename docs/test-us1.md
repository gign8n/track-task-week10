# วิธีทดสอบ US-1 สมัครสมาชิกและล็อกอิน

รอบนี้ทำ AC-1.1–AC-1.5 เท่านั้น ยังไม่มีส่วนสร้างทีม (US-2) หรือเลือกผู้รับงาน (US-3 / AC-3.4) เงื่อนไขมอบหมายได้เฉพาะสมาชิกทีมยังคงอยู่ใน docs/design.md และต้องบังคับทั้งหน้าจอกับฐานข้อมูลเมื่อทำ US-3

## เตรียมก่อนทดสอบ

1. เปิดไฟล์ supabase/migrations/20261114000100_us1_profiles.sql ใน VS Code แล้วคัดลอกทั้งหมด
2. เปิดโปรเจกต์ Supabase → SQL Editor → New query → วาง → Run เพียงครั้งเดียว ไฟล์สร้างตาราง profiles พร้อม RLS (กฎจำกัดสิทธิ์รายแถว) และ trigger (คำสั่งอัตโนมัติเมื่อสมัคร) หากมีตาราง profiles อยู่แล้วให้หยุดและแจ้งข้อผิดพลาดก่อน ไม่ลบตารางเดิมทิ้ง
3. สำหรับ workshop ไป Authentication → Sign In / Providers → Email → ปิด Confirm email → Save เพื่อให้สมัครแล้วล็อกอินทันที ตาม docs/plan.md
4. ตรวจ .env.local ในโฟลเดอร์ track-task-week10 ว่ามี NEXT_PUBLIC_SUPABASE_URL และ NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY ไม่ต้องเพิ่มค่าใหม่ และไม่ใช้ secret key ห้ามคัดลอกค่าจริงมาในแชท
5. เปิด Terminal ในโฟลเดอร์ track-task-week10 แล้วพิมพ์ npm run dev เปิด http://localhost:3000/login

## ทดสอบตามเกณฑ์ยอมรับ

| เกณฑ์ | ขั้นตอน | ผลที่ต้องได้ |
|---|---|---|
| AC-1.1 | กดสมัครสมาชิก กรอกชื่อ อีเมลใหม่ และรหัสผ่านอย่างน้อย 6 ตัว กดสมัคร | ไป /team ในสถานะเข้าสู่ระบบแล้ว แถบบนแสดงชื่อที่กรอก; /team แจ้งว่าส่วนจัดการทีมจะเพิ่มใน US-2 |
| AC-1.1 ข้อมูลไม่ครบ | ลองชื่อว่าง/ช่องว่างล้วน อีเมลผิดรูปแบบ และรหัสผ่านสั้นกว่า 6 ตัว | ไม่สมัครสำเร็จ แสดงข้อความตรวจข้อมูล; ระหว่างส่งคำขอปุ่มแสดงกำลังดำเนินการและกดซ้ำไม่ได้ |
| AC-1.2 | ออกจากระบบ แล้วใช้อีเมลเดิมกับรหัสผ่านผิด | ยังอยู่ /login และแสดง “อีเมลหรือรหัสผ่านไม่ถูกต้อง” |
| AC-1.3 | ล็อกอินด้วยรหัสผ่านถูก แล้วกดออกจากระบบ | ตอนล็อกอินแถบบนแสดงชื่อ; ออกจากระบบแล้วกลับ /login เปิด /team อีกครั้งต้องเข้าไม่ได้ |
| AC-1.4 | ล็อกอินในหน้าต่างปกติ ปิดเบราว์เซอร์ทั้งโปรแกรมโดยไม่ออกจากระบบ แล้วเปิดใหม่ภายในวันเดียวกันและเข้า /team | ยังล็อกอินและเห็นชื่อเดิม ห้ามใช้หน้าต่างไม่ระบุตัวตนทดสอบข้อนี้หรือเปิดตัวเลือกล้างคุกกี้เมื่อปิด |
| AC-1.5 | ในหน้าต่างไม่ระบุตัวตนที่ยังไม่ล็อกอิน พิมพ์ /team, /tasks, /my ทีละหน้า | ทั้งสามหน้าพาไป /login |
| NFR-3 | ทดลองส่งข้อมูลผิดและกดส่งแล้วสังเกตระหว่างรอ | มีข้อความภาษาไทย ไม่แสดงรายละเอียดภายในหรือค่าลับ; ข้อมูลชื่อและอีเมลยังอยู่เมื่อส่งไม่สำเร็จ |
| NFR-4 | เปิดเครื่องมือเบราว์เซอร์ F12 → เปิดโหมดอุปกรณ์ → ตั้งกว้าง 375px | ฟอร์ม แถบชื่อ และปุ่มไม่ล้นแนวนอน รวมกรณีชื่อผู้ใช้ยาว |

สมัคร A ในหน้าต่างปกติ และ B ในหน้าต่างไม่ระบุตัวตนด้วยชื่อ/อีเมลต่างกัน ตรวจว่าทั้งสองหน้าต่างแสดงเฉพาะชื่อของบัญชีที่ล็อกอินอยู่ ไม่สลับข้ามบัญชี

## ตรวจชื่อและสิทธิ์ข้อมูล

- Supabase → Table Editor → profiles ต้องมี user_id ตรงกับ Authentication → Users และชื่อถูกต้อง มีสัญลักษณ์ว่าเปิด RLS แล้ว
- Table Editor เป็นมุมมองผู้ดูแล จึงเห็นทุกบัญชีได้ ไม่ใช้เป็นหลักฐานว่าข้อมูลไม่รั่ว
- ทดสอบสิทธิ์โดยคัดลอก User UID ของ A จาก Authentication → Users แทน YOUR_USER_A_UUID ในคำสั่งด้านล่าง แล้วรันใน SQL Editor เป็น query ใหม่ จากนั้นทำซ้ำด้วย UID ของ B ไม่ต้องใส่ key หรือรหัสผ่านใด ๆ

```sql
begin;
select set_config('request.jwt.claims',
  json_build_object('sub', 'YOUR_USER_A_UUID', 'role', 'authenticated')::text,
  true);
set local role authenticated;
select user_id, display_name, email from public.profiles;
rollback;
```

ผลที่ต้องได้: A เห็น profile ของ A เพียงแถวเดียว B เห็นของ B เพียงแถวเดียว ตอนนี้ยังไม่เพิ่มการอ่าน profile เพื่อนร่วมทีมเพราะยังไม่ทำ US-2 ขั้นตอนนี้จำลองสิทธิ์ authenticated (ผู้ใช้ที่ล็อกอิน) ในฐานข้อมูล ไม่ใช่การทดสอบ publishable key ผ่านเครือข่ายจริง

## เมื่อพบปัญหา

- สมัครไม่ได้: ตรวจว่ารัน SQL สำเร็จแล้ว และปิด Confirm email สำหรับ workshop แล้ว หากเปิด Confirm email ไว้ ระบบจะแจ้งแทนการพาเข้า /team โดยไม่มีสถานะล็อกอิน
- ขึ้น “โหลดข้อมูลไม่สำเร็จ”: ตรวจตาราง profiles และอินเทอร์เน็ต แล้วกด “ลองใหม่” ห้ามปิด RLS เพื่อแก้ปัญหา
- npm ไม่พบใน Terminal: ปิดแล้วเปิด VS Code ใหม่หลังติดตั้ง Node.js และลอง npm run dev อีกครั้ง
- ก่อนทำ US ถัดไป เปิด Source Control ตรวจรายการเปลี่ยนแปลง แล้ว commit โค้ดและ SQL เก็บไว้ ไม่เพิ่ม .env.local ลง Git

## การตรวจอัตโนมัติ

ใช้ npm run lint และ npm run build ตาม package.json ปัจจุบันยังไม่มีคำสั่ง npm test การสมัคร ล็อกอิน รหัสผิด ความคงอยู่ของสถานะ และสิทธิ์ข้อมูลจริง ต้องทดสอบหลังผู้ใช้รัน SQL และตั้งค่า Supabase แล้ว
